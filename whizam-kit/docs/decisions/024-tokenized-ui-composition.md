# 024 — Consommation UI exclusivement par tokens

**UI-ARCH-04 — adoption du socle des nouveaux projets :** [décision 037](037-project-ui-foundation-adoption.md). Tailwind `project:` sans nouveau Preflight, thème dérivé du DTCG projet dans le writer transactionnel ; Button/Field sur React Aria, API et alias locaux conservés. Consommation contrôlée par utilitaires statiques liés aux bindings ; pas de référence aux valeurs outil. Création/export à qualifier séparément, projets existants et anciens journaux préservés ; Electron hors mandat. Cette adoption ne constate pas la qualification, suivie dans la fiche UI-ARCH-04.

**UI-ARCH-03 — adoption bornée :** [décision 036](036-first-ui-slice-adoption.md). Les nouvelles surfaces du chrome consomment leur autorité DTCG outil et leurs styles Tailwind dérivés ; les valeurs projet et règles historiques restent inchangées. Le contrôle outil couvre classes/variables et absence de références projet ; aucune nouvelle capacité du writer. Socle des projets et Electron hors tranche.

**Complément approuvé DS-ARCH-01 :** [027](027-dtcg-authority-and-css-recipes.md) déplace les valeurs/références en JSON DTCG et sépare les recettes CSS contextuelles. Toute valeur visuelle pilotable reste reliée à un token ; les opérations/mots-clés structurels sont explicitement contrôlés dans les recettes. Une expression responsive n’est plus stockée comme primitive CSS opaque. Les anciennes variables de composition restent des sorties compatibles lorsque nécessaires. Cette évolution ne rend libres ni les valeurs UI ni les propriétés éditables, et ne crée pas une sixième responsabilité.


2 novembre 2026 — règle produit explicitement validée par l’utilisateur, réalisation DS-EDIT-52. Toute propriété visuelle UI consomme un token sémantique ou de composant, jamais directement une primitive ou une valeur brute. Les chaînes token de composant → primitive et token de composant → sémantique → primitive restent autorisées ; aucune couche sémantique artificielle. L’IA documente l’usage, recherche les tokens existants par sens et compatibilité, puis prépare seulement les manques. Les mots-clés structurels/reset ne créent pas une échelle visuelle. L’éditeur Storybook reste hors périmètre.

ui-composition.yaml détient les primitives CSS de composition et les tokens/consommateurs hors matrice V1 (ombres, transitions, dimensions fluides notamment). Valeurs opaques CSS avec caractères de déclaration refusés, références fermées, justification et consommateur explicites ; le générateur existant les joint à tokens.generated.css. Les primitives canoniques et rôles de texte compatibles sont réutilisés. La règle primitiveColorSamples dérive un token de composant par primitive couleur consultée dans le catalogue ; même les nuanciers passent ainsi par un token, et leur géométrie est mutualisée. Aucun nouveau contrôle éditable, adoption Base UI ou catalogue de primitives inventé ; les 188 réglages V1 gardent leurs identités, types et validations. La génération et validate:design-system refusent références absentes, consommateurs déplacés, consommation directe d’une primitive et valeurs visuelles brutes sur les propriétés contrôlées. Les consommateurs sémantiques de composition participent à l’impact partagé.

Le manifeste inclut la nouvelle autorité et l’outillage. Ses anciens reçus restent attachés à l’ancienne version ; ne pas les convertir ni les supprimer pour démarrer. Une prévisualisation neuve peut reprendre les seuls YAML de valeurs, sans journaux ni comptes, en conservant l’ancienne instance. Pas de publication.
