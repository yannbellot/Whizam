## Résultat livré

DS-EDIT appartient à UI Lab. Storybook conserve navigation standard, Controls/Docs, propriétés, exemples React, vrais composants, états et documents du design system. Son addon, ses outils/panneaux/thème et adaptateurs d’édition, son décorateur de projection et ses canaux sont supprimés ; aucun writer, bootstrap de capacité ou connexion Codex ne peut être réactivé dans cet hôte par l’ancien indicateur. Le lanceur documentaire ne crée plus l’environnement d’édition et retire les variables de capacité/identité.

Le socle client exige le port explicite fourni par UI Lab. Le repli DOM/parent et le renouvellement historique à `/` sont retirés ; le transport propre au document atelier et sa vérification de racine restent inchangés. Les stories des catalogues importent directement TokenCatalog, sans wrapper dans `.storybook/editor/`. Les cibles déclarées dans les fixtures communes restent des données de scènes UI Lab, sans API Storybook ni édition dans les stories.

Le seul raccordement serveur documentaire est un **lecteur** : barrière HTTP commune sur le serveur Storybook extérieur, et participant Vite notifiant le rechargement après publication cohérente. Le fichier conventionnel `.storybook/middleware.mjs` est remplacé par ce lecteur ; son ancien contenu writer est retiré. Aucun store writer, agent ou bootstrap n’y est importé. Protéger seulement Vite laissait les pages HTML servies avant lui hors barrière : les deux niveaux sont donc couverts. UI Lab conserve sa notification sans rechargement destructeur du brouillon.

Manifeste fermé **v16**, protocole de sauvegarde v4 inchangé. Les dépendances mortes de l’ancien hôte/configurations sont retirées ; les consommateurs documentaires utiles restent couverts par la révision, sans constituer un CLI/manager/index nécessaire au lancement UI Lab. Les dix sources éditables restent les mêmes ; **22 autorités/fiches YAML et les sept dérivés sont identiques** au témoin E. Aucun changement SQL, de dépendance, de valeur ou de direction visuelle.

Les suppressions concernent les seuls fichiers suivis. Le non-suivi préexistant `.storybook/editor/SemanticStyles.tsx`, les copies suffixées ` 2` et `frontend/` sont préservés et exclus du paquet source testé. Aucun ancien journal ou compte converti/purgé, aucune instance de recette ou copie externe actualisée.

## Diagnostics et corrections

1. Premier test unitaire bloqué par le sandbox lors de la réservation d’un port local : retest autorisé dans la copie fictive, sans changement des protections du produit ; réussite.
2. Avec Storybook ouvert, une réservation de lecture restait active et faisait refuser la sauvegarde. Observation des journaux/markers, puis lecture du middleware de compression de la version installée : il redirige `res.on` vers le flux compressé, et une réponse peut être abandonnée pendant les opérations asynchrones. Le helper commun observe maintenant les événements de la **réponse HTTP native**, avant toute réservation/préparation, libère les marqueurs même si close précède la suite, puis retire ses écouteurs. Le [test de régression](../../tests/unit/preview-reader.test.ts) détourne `.on`, ferme la réponse pendant la préparation et vérifie la libération réelle du marqueur sans appeler next. Le parcours réel avec compression/rechargement puis sauvegarde est rejoué avec succès.
3. Protéger le seul Vite documentaire laissait `/iframe.html` répondre 200 pendant interruption : lecteur commun ajouté à l’entrée HTTP Storybook extérieure. Les lectures des deux hôtes sont désormais réellement bloquées, sans writer ajouté à Storybook.
4. Des campagnes initiales en parallèle sur la même racine ont effacé le dossier commun de résultats pendant le parcours live, causant une erreur de journal ENOENT. Campagnes de cycle de vie rejouées seules ; captures reprises sur une copie distincte. Aucun résultat perdu n’est présenté comme preuve disponible.
5. La collecte additionnelle de captures n’avait pas son cache Chromium ; le premier lien créé dans un dossier déjà présent était imbriqué. Lien corrigé vers le cache d’outil existant, deux parcours de capture rejoués. Aucune installation/préférence globale modifiée. Les échecs et retests restent séparés dans les journaux.

6. Le contrôle global de formatage signalait une ligne préexistante dans workspace.module.css. Mise en forme seule ; comparaison PostCSS des règles avec normalisation des blancs autour des virgules de listes de sélecteurs, sans changer les valeurs ou autres espaces de sélecteur. Les règles sont identiques ; formatage global, rebuild application et 14 parcours compilés rejoués. L’empreinte avant cette seule mise en forme est distinguée de celle du paquet final.

Les premiers diagnostics de lifecycle sont instrumentés uniquement dans la copie debug ; aucune trace ou API de panne ajoutée au produit. Le test de récupération instrumente son bootstrap fictif avant génération et conserve les mêmes octets pendant reprise/redémarrage. Les contrôles finaux utilisent le code livré hors cette injection de test explicitement bornée.
