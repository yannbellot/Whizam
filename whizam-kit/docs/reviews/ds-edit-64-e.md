## Version, périmètre et résultat

L’atelier édite et sauvegarde sans démarrer Storybook ; ce dernier restitue ensuite les composants enregistrés, leurs propriétés, code React et états. La tranche F reste distincte : addon/adaptateur Storybook encore présent, writer désactivé par défaut. Aucune instance de recette ou copie externe actualisée, aucun compte connecté, aucune inférence réelle, publication, CI distante ou déploiement. Les modèles de suivi du kit restent non initialisés ; statuts de fabrication consolidés dans le lab.

## Conservation des rendus et de l’instance

**Référence à valeurs constantes.** `node scripts/check-design-system-migration.mjs before` sur le build de référence du candidat puis `after` sur le build produit séparément dans le kit extrait/renommé, tous deux construits à valeurs constantes avant la modification fictive persistée : **14 PNG identiques octet pour octet et 14 instantanés de styles calculés/géométrie identiques**, sept états/scénarios aux deux formats. [Empreintes comparées](ds-edit-64-e/renders.json). Les **188 cellules préparées** modifient la propriété CSS attendue ; isolation Field/SelectField, Notice/Panel, propagation partagée et rétablissement conformes : [résultat](ds-edit-64-e/wiring.json). Cette comparaison prouve l’extraction/renommage à version constante ; les preuves A–D documentent les changements précédents de migration.

**Valeur réellement enregistrée.** Dans la copie installée, sauvegarde locale de Button en `#2468ac`, arrêt du store puis renommage et déplacement avec espaces. À chaque emplacement, réémission de la **même** requête, même réponse, identité/révision/génération et empreintes des dix sources/sept dérivés. Nouveau contrôle identique après les essais navigateur : [reçu sélectionné](ds-edit-64-e/receipt.json), `receipt.log`. Le véritable atelier lancé depuis le dossier déplacé recharge la valeur et rend `rgb(36, 104, 172)` aux deux formats, sans requête de CLI/manager/index Storybook. Après arrêt du writer, Storybook est reconstruit depuis ces valeurs puis ses Docs sont relus : [résultats](ds-edit-64-e/moved-kit.json), `moved-final.log`. Le Loading garde sa propre valeur : aucune propagation locale inventée.

**PostgreSQL.** Deux instances isolées, trois lignes synthétiques chacune. Arrêt de l’instance principale sans suppression de volume, renommage puis déplacement, migrations/seed rejoués. Données complètes incluant identifiants et dates, configuration privée et volume restent identiques. Le témoin garde contenu/configuration/volume et instant de démarrage, donc n’est ni redémarré ni modifié : [comparaisons](ds-edit-64-e/data.json), `data.log`. Nettoyage limité aux deux identités fictives après vérification ; aucun transfert interhôtes déduit de cette preuve.

## Diagnostics, limites et réserves visibles

- Le premier essai Storybook ne trouvait pas le cache Chromium dans l’extraction : échec conservé, cache d’outil explicitement sélectionné puis retest réussi. Le premier runner navigateur était bloqué par le sandbox au bind loopback ; exécution autorisée sur les ports fictifs, sans changement de protection du kit.
- Le premier appel Docker runtime visait l’ancien chemin de copie déjà déplacé : corrigé vers le nouvel emplacement puis build réussi. Aucun défaut applicatif déduit de ce diagnostic.
- Le script ponctuel de passation utilisait un mauvais chemin CLI Storybook puis supposait Show code de rôle button/bloc pre. Le lanceur livré et le vrai contrôle **switch Show code** sont utilisés au retest et dans le test durable ; exemples React visibles. Les erreurs restent dans `moved*.log`.
- Les premiers nouveaux tests utilisaient une dimension équivalente à la valeur initiale, puis cherchaient une propriété de contrôle sur la partie racine d’un champ. Ils ont correctement rencontré une action désactivée/une option absente ; runner initial expiré. Données distinctes et sélection explicite de Contrôle corrigées, six parcours rejoués sans assouplissement du produit. Le formatage du nouveau test Storybook a aussi été corrigé puis contrôlé.
- Installation npm réussie avec avertissement de scripts de dépendances non approuvés ; les builds réellement exécutés ont réussi. Avertissements Rollup d’annotations et de taille de chunks Storybook conservés ; pas d’optimisation supplémentaire engagée.
- **Réserve visuelle non bloquante :** à 390px, la table native de propriétés Storybook peut étendre la page horizontalement. Les informations restent consultables par défilement ; la passation développeur est vérifiée en desktop et mobile, sans prétendre à une table Docs entièrement responsive. UI Lab conserve ses vues mobile Aperçu/Réglages. À examiner dans la recette, pas de refonte visuelle décidée en E.
- Firefox/WebKit, Windows/x64, navigateur Linux, coupure matérielle réelle et transfert de données vers un autre hôte non vérifiés. Aucun nouveau test d’installation système vierge, découverte native ou efficacité d’assistant. Les qualifications antérieures conservent leur portée dans la [matrice](../compatibility.md).
- Pas de nouvel audit réseau de dépendances ou décision de licence ; aucune dépendance ajoutée. Les réserves de sécurité antérieures et l’autorisation distincte de publication restent applicables.

## Revues et conclusion de tranche

Procédures test-user-flow/prepare-handoff/prepare-release, puis rôles Design Reviewer, Technical Reviewer/QA, Security Reviewer et Distribution Reviewer. Skill de fabrication `lab-qualify-distribution` du dépôt concepteur utilisé dans son périmètre de qualification ; son exécution n’est pas un prérequis du kit extrait. **Revues séquentielles par le même agent, non indépendantes.**

- Design : références comparées sans changement de valeurs, captures UI Lab et Docs examinées, distinction brouillon/enregistré, portée explicite et assistance facultative. Usage clavier et mesures réelles vérifiés ; réserve de table mobile consignée, acceptation visuelle non déduite.
- Technique/QA : boucle YAML → génération → vrais composants → UI Lab/Storybook contrôlée. Reprise/idempotence après interruption et déplacement, builds séparés et conservation SQL avec témoin établis. Aucun moteur d’édition doublonné, aucun changement de protocole/manifeste ou de modèle de données. Recherche des imports du socle client/serveur, de la coque et des lanceurs sans import Storybook ; les chemins `.storybook` conservés dans le manifeste sont des consommateurs documentaires couverts par la révision, pas un CLI/manager/index requis pour le lancement UI Lab.
- Sécurité : entrées locales Host/Origin/capacité, fichiers privés, bootstrap réservé au document, refus d’un deuxième writer et absence dans le runtime testés. Sources extraites sans état privé ; connexion optionnelle uniquement simulée. Revue proportionnée, sans certification ou indépendance revendiquée.
- Distribution : 42 liens internes, installation verrouillée, sources sans parent/Git, Linux sans montage, noms/chemins avec espaces et données conservées vérifiés. Kit d’agents structurellement conforme ; reprise humaine/native distincte. Aucun rôle/skill modifié, donc pas de nouvelle Instruction Review.
