## Cause et correctif

En revue — qualification technique acquise, acceptation humaine différée. Lecture des versions installées : Vite 7.3.7 (`dist/node/chunks/config.js`, restartServer) crée `_createServer` avant `server.close`. React Router 7.18.4 (`dist/vite.js`, watch) supprime `.react-router/types` pendant cette création, sans attendre l’ancien watcher ; le service d’édition a aussi un propriétaire exclusif. Un redémarrage interne peut donc faire se chevaucher les suppressions/écritures de types et les acquisitions du store. L’origine extérieure des notifications reste non attribuée ; le chevauchement induit dans le processus est identifié. Les simples relances précédentes n’avaient pas corrigé ce cycle.

Le plugin compare les octets des fichiers de configuration/dépendances et env activés : notifications sans changement ignorées. Pour un vrai changement, message IPC fermé au lanceur ; ce dernier termine l’ancien enfant et n’en démarre un autre qu’après son événement exit, avec une nouvelle capacité. La surveillance par interrogation à une seconde concerne seulement l’enfant et couvre aussi le watcher interne React Router. Elle seule était insuffisante : le premier essai polling s’est arrêté avec ENOTEMPTY. Le lanceur ne relance pas sur une erreur inattendue ; celle-ci reste visible. Modèle, protocole, autorités de valeurs et dépendances inchangés ; manifeste v21.

## Preuves et limites

Copie native de comparaison : rafale de 60 × quatre touches de fichiers, puis vrai changement de configuration ; serveur finalement sans service disponible (snapshot HTTP 503). Essai polling seul : ENOTEMPTY reproduit. Correctif complet : rafale sans changement de PID writer, vrai changement de configuration pris en compte, ancien PID disparu avant nouveau, sauvegarde synthétique puis relecture réussies. SIGKILL synthétique ensuite : erreur visible, aucun processus relancé en boucle. [Preuve sélectionnée](../reviews/ds-edit-69/qualification.json). Script portable `scripts/test-workshop-stability.mjs`, avec copie privée synthétique et logs/résultat. Ses gardes refusant propriétaire vivant et transaction active sont vérifiés séparément.

Deux premiers essais du script avaient leurs fixtures dans test-results, chemin ignoré par Vite : absence de véritable événement, assertion de remplacement échouée. Fixture déplacée vers test-fixtures (ignorée par Git, surveillée par Vite), puis régression réussie. Le garde refuse maintenant un hôte actif : créer une fixture avec tsconfigs sous un serveur déjà lancé peut perturber ce serveur. Les échecs initiaux restent dans `.local/ds-edit-69/` ; aucun résultat vert revendiqué pour eux.

Types et lint réussis (premier typecheck : envDir pouvant valoir false, corrigé). Campagne persistante : 13 parcours réussis et un cas mobile échoué sur attente de confirmation pendant une exécution concurrente de la fixture de stabilité ; cause précise de cet échec non établie, interférence de surveillance plausible. Cas rejoué seul : réussi (11.1 s). Les 14 parcours sont ainsi qualifiés, sans revendiquer une nouvelle campagne complète 14/14 simultanément verte. Les tests doivent rester séquentiels dans une même racine. Assistance uniquement simulée. Pas de nouvelle campagne exhaustive serveur/Linux/Windows ou audit de dépendances ; aucune modification de schéma/service de stockage à qualifier.

Revues séquentielles, même agent, non indépendantes : technique — remplacement au niveau processus et absence de chevauchement observés, vrai changement conservé, pas de génération avant récupération ; sécurité proportionnée — IPC limité au processus enfant local, capacité renouvelée, limites loopback inchangées, empreintes jamais journalisées avec contenu sensible, aucun masque des erreurs ou retrait de verrou ; design — pas de changement visuel, atelier et réglages existants observés prêts, aucun rendu accepté au nom du designer. Les brouillons en mémoire ne deviennent pas persistants ; un vrai changement de code peut demander une actualisation de l’interface.
