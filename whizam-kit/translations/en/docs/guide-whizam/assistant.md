# Working with your assistant

Describe what the person using your application should understand or be able to do. Locate your request within a page or journey and state constraints to preserve. Share only references and content you are authorized to share.

## Make an actionable request

> “On the Contact page, visitors must understand required fields before submitting. Prepare a proposal while preserving other pages. Here are the texts and visual reference.”

Specify whether you want an explanation, preparation or implementation. Preparation produces scope and criteria for review; it does not start development. For implementation, the assistant analyzes the request and applies the kit’s approval rules. Authorization already received for the same scope need not be repeated for each operation.

You should be able to identify the expected result, temporary elements, checks and decisions that belong to you. If a proposal is too vague, ask for observable outcomes before deciding.

## Understand the exchange

Apply [initial scoping](../agents/project-intake.md): conditional questions, conversational follow-ups and resumption from the brief/checkpoint. Do not ask which assistant is used; use its entry-point policy. Collect missing documentation languages at Q10 according to [Project languages](../agents/languages.md).

Questions use native client controls when available and permitted. If a question is not clickable, answer with its label or request a numbered list. The kit does not guarantee identical rendering across assistants.

A model or effort recommendation helps you choose a configuration; it does not change the tool automatically. [Adapters and their limits](../compatibility.md) distinguish included resources from completed tests.

Do not share passwords or keys in chat. The assistant should explain required fields and offer [local private entry](../agents/private-configuration.md), with a file fallback when necessary.

To clarify a need, read [Scoping a first version](cadrer-version.md). The [kit instructions](../../AGENTS.md) and [decision protocol](../agents/user-decisions.md) remain authoritative.
