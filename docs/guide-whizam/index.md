# Découvrir Whizam

Whizam accompagne les designers UX/UI et Product Designers pour concevoir, construire et transmettre une application web avec un assistant capable de travailler dans ses fichiers. Le kit contient un socle applicatif, des composants, des méthodes et des outils de vérification. Votre application prend le nom et les objectifs de votre brief.

Vous apportez l’intention, les contenus, les références et les décisions de conception. L’assistant examine l’existant, propose une tranche de travail, la réalise dans le mandat convenu et explique comment examiner le résultat. Vous gardez la décision d’accepter une livraison.

## Choisir son point de départ

- Vous recevez le kit : commencez par [Préparer son kit](preparer-kit.md), puis [Créer son premier projet](premier-projet.md).
- Vous avez déjà un projet : lisez [Reprendre et transmettre](reprendre-transmettre.md).
- Vous voulez corriger ou enrichir une version : consultez [Demander une évolution](demander-evolution.md).

## Se repérer dans les outils

| Accès | Ce que vous y examinez |
| --- | --- |
| Application | Les pages et parcours effectivement réalisés pour votre projet. |
| Storybook | Les composants du projet, leurs variantes et états documentés. |
| Documentation | Ce guide, les choix et le suivi du projet, ainsi que les références techniques. |

Au départ, l’application et Storybook n’ont pas de contenu métier. Le portail contient les guides et les modèles de suivi : cet état est normal. L’assistant présentera les accès réellement vérifiés au moment de la revue ; leur adresse dépend des services locaux.

Dans le portail, **Documentation designer** rassemble les contenus et le suivi de votre projet ; **Documentation technique** explique son fonctionnement. Le présent guide décrit comment avancer avec Whizam.

Pour commencer : « Aide-moi à préparer le kit et explique ce que je devrai fournir pour mon premier projet. » Voir aussi les [questions fréquentes](questions-frequentes.md).
