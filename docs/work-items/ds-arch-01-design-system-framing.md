## Résultat attendu

Le kit explique et applique cinq responsabilités : **Primitives, Decision Tokens, Component Tokens, Components, Patterns**. Sa documentation et ses catalogues s’organisent sous **Foundations, Components, Patterns**. Ces rubriques ne forcent pas une chaîne technique unique : un Component Token peut atteindre directement une Primitive ; un Decision Token peut référencer un autre Decision Token compatible, justifié et sans cycle.

Les Decision Tokens distinguent explicitement décisions sémantiques et non sémantiques. Un rôle documenté justifie les premières ; une convention partagée explicite justifie les secondes, indépendamment du nombre de consommateurs. Une valeur identique ne suffit à créer ni décision commune ni fusion. Les Component Tokens restent propres à leur composant, sans référence à un autre Component Token ; toute valeur non primitive rejoint une Primitive par référence.

Le référentiel représente les tokens selon DTCG 2025.10. Les règles de grille, responsive, composition, mouvement et accessibilité restent documentées même sans token. UI Components et Layout Components peuvent être simples ou composites ; les Patterns décrivent une solution d’usage récurrente, avec classifications Interaction et Layout cumulables. La conception reste progressive et component-first, à partir des besoins réels.

**Hypothèse proposée : migration sans changement visuel intentionnel.** Conserver valeurs, unités, comportements, réglages enregistrés et distinction modification locale/attribution/base de rétablissement. Vérifier les identités et alias, ou documenter chaque correspondance indispensable. Cette hypothèse est réversible et à présenter en recette ; elle n’est pas une nouvelle acceptation visuelle.

Exclusions : nouveau framework, bibliothèque UI, backend, synchronisation Figma, échelles ou breakpoints imposés, catalogue exhaustif, nouveaux composants/patterns sans besoin réel, nouvelle surface d’édition, réactivation des anciens onglets supprimés, comptes/inférence IA réels, données métier et copies externes. Storybook reste documentaire, UI Lab conserve l’édition locale ; aucun transfert inverse du writer. Aucune clôture J4/J5, acceptation humaine ou publication incluse.
