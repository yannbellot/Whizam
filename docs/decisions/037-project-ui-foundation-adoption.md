# 037 — Adoption du socle UI des nouveaux projets

**14 novembre 2026 — Adoption autorisée par le mandat explicite UI-ARCH-04, avec alignement des autorités avant code.** La qualification est à établir ; aucune acceptation humaine globale ou mise à jour d’un projet existant n’est déduite de cette décision.

Appliquer le cadrage 035 au socle des nouveaux sites/web apps : React Aria et HTML sémantique, Tailwind v4, valeurs et références DTCG propres au projet. Première famille bornée à Button et Field, avec maintien de leur API de formulaire, identité et marqueurs d’inspection. CSS Modules conservés pour les surfaces non converties et le CSS spécialisé ; aucun Preflight ajouté globalement, aucune nouvelle palette.

Le thème `src/styles/project-theme.generated.css` est un dérivé du pipeline existant, publié et récupéré dans la même transaction que les autres dérivés. Préfixe Tailwind `project:` distinct de `ui:`. Les utilitaires fermés `token-<part>-<property>-<state>` se déduisent des propriétés CSS validées et consomment les alias `--adl-local-*` existants ; les noms de thème typés exposent ces mêmes alias. Ce choix conserve les substitutions par variante/occurrence. Les classes sont statiques, les consommateurs et la correspondance avec les bindings sont contrôlés ; aucune valeur arbitraire ou référence aux tokens du chrome. Aucun second générateur ne publie ces sorties.

Le manifeste de révision évolue pour inclure sources et dérivé, sans ajouter d’opération éditable ni convertir un ancien journal/reçu. Les anciennes transactions restent sous leur outillage ; pas de suppression de verrou pour démarrer. Les listes de création/export sont adaptées à la seule complétude du socle et qualifiées séparément. L’autonomie signifie que runtime et Storybook n’exigent aucune installation/service/compte Loomata externe ; les outils autonomes du dossier peuvent être conservés sans import runtime du chrome dans les pages produit.

Les projets existants, bases, données privées, ressources externes et fenêtres personnelles sont préservés. L’exécution ne comprend ni Electron, ni packaging natif, ni nouveaux profils d’export, ni fonctionnalités métier. Versions verrouillées réutilisées sans mise à jour générale. Guide autonome : [socle UI du projet](../architecture/project-ui-foundation.md). La qualification de fabrication est suivie sous UI-ARCH-04, distinctement de ce guide livré.


Adaptation API inspectée : RAC Button accepte une valeur string et des événements FocusEvent<Element>, alors que l’API actuelle ButtonHTMLAttributes autorise valeurs numériques/listes et événements HTMLButtonElement. Choix délégué : conserver le bouton HTML, utiliser `useButton` et `mergeProps` de React Aria 3.53.1, déjà dépendance transitive verrouillée, désormais déclarée directement. Aucun cast de props, mise à jour de version ou remplacement de callback onClick par onPress. Field reste composé avec React Aria Components 1.22.1 ; tests de formulaire et de soumission requis.
