## Résultat

Loomata propose une quatrième vue persistante **Assistance**, alimentée par le même cœur Node dans `/application` et accessible au dossier par `ai.open`. Connexion officielle personnelle Codex, texte progressif, liste/lecture de sources, proposition d’un fichier à autoriser/refuser, interruption et reprise d’une session fournisseur persistante. UI Lab, Storybook et l’aperçu restent distincts et conservent leurs documents. Aucun projet métier arbitraire créé.

La connexion a été effectuée personnellement par le porteur dans le navigateur officiel. L’intégration utilise son propre état privé et un binaire officiel 0.167.0 installé automatiquement depuis le verrou npm/SRI, vérifié ensuite par reçu SHA256. Aucun identifiant de fabrication lu, copié ou exporté. Une première connexion a échoué ; elle a été annulée puis relancée. L’état connecté seul n’a pas servi de preuve d’inférence.

## Échecs conservés et corrections

L’appel réel par outil dynamique a échoué avec « code-mode host is disabled ». Le contrôle automatique a refusé l’action d’activation de `code_mode_host` au motif d’affaiblissement persistant des protections. Cette action n’a pas été exécutée ni contournée. La solution livrée garde les moteurs et outils natifs désactivés : le modèle retourne un schéma JSON fermé, le broker valide puis réalise les actions permises. Les échanges et écritures réels ci-dessus qualifient cette solution. L’échec initial reste visible dans les artefacts privés, sans être renommé en réussite.

Deux premiers essais natifs se sont arrêtés avant le chat : un nouveau consommateur CSS utilisait une référence de composition non préparée, signalée par l’inventaire et empêchant l’atelier d’être prêt. Correction Builder : réutiliser la composition App et les composants existants, limiter le nouveau CSS au structurel ; régénération sur les seules copies inactives, atelier prêt et essais natifs réussis. Un ajout de test Swift a ensuite échoué à compiler à cause d’une expression asynchrone dans une autoclosure ; le pilote a été corrigé et la commande finale a réussi. La revue finale a aussi identifié la nécessité de comparer les chemins protégés sans distinction de casse sur macOS : correction Builder et refus des variantes `Package.json`, `SRC/design-system` et `Scripts` vérifiés par le test du broker. Le budget de liste de 1 000 entrées est aussi vérifié sur un dossier de 1 002 fichiers. L’assertion de casse a d’abord rencontré le refus préalable d’un nom réservé aux secrets ; un témoin non secret a permis de vérifier distinctement la protection DS. Les échecs restent conservés. L’extraction a d’abord échoué car la vieille copie QA B ne contenait pas encore un document C exigé par la liste fermée. La copie inactive a été complétée depuis les sources sélectionnées actuelles, sans retirer le contrôle ; extraction/préparation/CLI ont ensuite réussi.

Les premiers contrôles lint/format et la première installation npm ont également échoué : effet React synchrone et format corrigés ; fichiers npm user/global distincts au lieu du même `/dev/null`. Le SDK 27 par défaut reste incompatible avec le compilateur installé ; le builder existant utilise le SDK 26.5 disponible. Aucun outil global, réglage de confidentialité ou service de session modifié.

## Revues et réserves

Revues **séquentielles, même agent, non indépendantes** sur le diff final. Design : libellés, attente, données conservées, décisions explicites et rendus desktop/mobile examinés ; références visuelles externes absentes, direction visuelle non acceptée au nom du porteur. Les contrôles de connexion adjacents et la présentation longue de l’historique restent une réserve d’ergonomie, sans bloquer le cycle qualifié.

Technique : entrée native/CLI jusqu’au service durable, isolation de l’installation/projet, idempotence, corrélation des événements/accords, sauvegardes atomiques et révision vérifiés ; tests corrigés relus. Sécurité ciblée : origine/Host/capacité, canal de contrôle propriétaire séparé du DOM, fichiers exclus, demandes natives refusées, politique OS, rendu texte et intégrité privés vérifiés. Aucune vulnérabilité bloquante démontrée dans ce périmètre ; ce constat n’est ni un audit indépendant ni une garantie globale. Les races hostiles entre processus du même compte et les secrets placés dans une source publique ordinaire ne sont pas couverts par une promesse de confinement absolu.

Un seul échange actif par installation ; les écritures portent sur des fichiers texte, un par accord, et ne lancent ni shell, installation, Git, migration ou modification directe des autorités DS. Le chat guide vers UI Lab pour le DS ; il ne remplace pas son writer. Profil de commandes sans réseau, mais connexion/inférence officielles en ligne. API de profils/sortie expérimentales et version verrouillée : requalification avant mise à jour.

macOS arm64 uniquement. Node/npm restent prérequis ; installation sans Node, autres CPU/OS, ZIP, signature/notarisation, mise à jour et distributions finales restent E–F.
