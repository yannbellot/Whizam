La [table historique](../design-system/token-migration.json) conserve les 28 références de primitives d’origine, les 41 styles et 188 identités de composants ; les 24 alias restent compatibles. Une primitive partagée entre espacement et corps de texte est scindée par famille, sans conversion d’unité. Les provenances regroupées restent dans `origins`, avec les métadonnées d’origine dans cette preuve datée.

Les huit sources réellement enregistrées de l’ancienne recette ont été importées dans `.local/ds-edit-15/saved-instance`, sans journal ni compte : comparaison intégrale des 188 valeurs de composants, 41 styles et 24 alias conforme. ## Diagnostics résolus

Le premier encodage YAML créait des ancres pour des provenances partagées ; le sérialiseur de migration produit désormais des objets distincts sans alias. Le premier contrôle du propriétaire était trop large : le cas prouvé disparu sans reçu est admis sans retirer son fichier ; propriétaire vivant, état douteux, récupération et reçu restent bloquants. Des assertions/fixtures visaient les anciens noms ou les anciens objets d’exception ; elles suivent maintenant la chaîne courante, sans réduire les contrôles de valeurs et de portée.

Le canal manager doit publier aussi les identités de composants ; la sélection attend la confirmation d’une génération compatible. Le retour vers l’usage sélectionne explicitement Apparence. Les tests ont été raccordés aux états de drawer natif et aux titres documentaires réels. La première campagne dev groupée a atteint la limite du runner à 120 s après des échecs ; les deux campagnes complètes par format passent. Les refus réseau locaux et le mauvais cache Chromium ont été diagnostiqués puis relancés avec les seuls accès/cache de test nécessaires. Aucun assouplissement de protection applicative ni installation globale.
