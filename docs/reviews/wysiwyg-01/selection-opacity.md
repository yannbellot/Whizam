# WYSIWYG-01 — Sélection et curseur d’opacité

16 novembre 2026. Cible application. Base `134f8b1`, branche codex/wysiwyg-01-selection-opacity. **En revue : qualification technique acquise, acceptation humaine différée.** [Empreintes des sources](selection-opacity-sources.json). [Mandat et critères](../../work-items/wysiwyg-01-selection-opacity.md).

Le panneau distingue les champs de structure et les champs du texte en fonction du nœud DOM réellement touché. Bouton → fond, contour, disposition, dimensions et espacement ; libellé → typographie et opacité. Les champs enregistrés sont filtrés par partie exacte, puis par propriétés compatibles ; un texte non enregistré ne reçoit pas ceux du parent. Les nœuds texte dans les exemples fournis sont déjà matérialisés par React ; le code de sélection ne réécrit pas le DOM. Pour un élément qui rend son propre texte avec une structure, les champs propres aux deux familles restent disponibles.

Le fond du canvas et le chrome de la galerie n’ont pas de contour de survol et ne peuvent pas devenir une cible de retouche. Un clic sur le fond désélectionne. Le brouillon de tokens conserve ses actions sans réexposer les champs d’un élément qui n’est plus sélectionné. Le titre visible, le message technique et le bouton de remontée ont été retirés ; le nom accessible de la région, les alertes et les confirmations restent en place.

Le curseur natif est aligné à droite du champ et synchronise la valeur avec la projection. La trace WebKit a montré une perte de focus entre l’appui souris et le premier événement input. L’identifiant du geste du curseur est maintenant distinct de celui des autres champs : les événements natifs restent associés au bon glissement. En recette WebKit : 1 → 0,24 pendant le geste → 1 après une seule annulation ; une deuxième annulation restitue la saisie précédente de 0,5. Les couches CSS générales avaient d’abord écrasé les valeurs fond/rayon du switch, corrigées dans la même couche de styles. La largeur de l’atelier et de l’iframe est bornée ; la galerie contient ses exemples sur une colonne réductible.

Types, build d’application et build Storybook réussis sur la copie isolée des sources suivies. Les 16 tests composition et contrats passent. Les copies locales préexistantes ne participent pas aux contrôles et ne sont pas modifiées. Commandes via sh scripts/with-runtime.sh : npm run typecheck, build, build-storybook ; npm run docs:design-system:check ; node --test tests/ui-composition.test.mjs tests/visual-intents.test.mjs ; ESLint ciblé ; node scripts/test-visual-inspector-ui.mjs --application, puis --application --webkit. Journaux ignorés selection-opacity-*. Les premiers tests sont conservés : styles du switch écrasés par la couche de l’inspecteur, annulation WebKit fractionnée, clic de fixture tombant sur le titre plutôt que sur le conteneur, puis assertion d’un ancien message d’en-tête. Les correctifs et assertions remplacées sont couverts par la dernière campagne. Deux essais concurrents ont aussi rencontré un service local occupé ou un délai au rafraîchissement après écriture ; qualifications finales réussies sous Chromium et WebKit, ce dernier seul.

Revues design et technique séquentielles, même agent, non indépendantes. Comparaison à la capture fournie pour la position et l’alignement du curseur ; validation fonctionnelle par les parcours. Revue sécurité ciblée du diff : ni entrée externe, ni permission, endpoint, publication, modification des autorités de tokens ou changement de données utilisateur.
