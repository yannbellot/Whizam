# Bibliothèque commune de skills

Chaque dossier contient son SKILL.md canonique au format Agent Skills. [catalog.json](catalog.json) indexe les responsabilités, leurs sources, ressources requises et les [quatre rôles](../agents/builder.md). La bibliothèque est extensible selon les besoins validés ; son nombre déclaré vérifie la complétude de la livraison courante, sans fixer de plafond. Toutes les sources, adaptations et références requises sont internes au kit, indépendamment de son nom et de son chemin.

Lire le seul skill utile et le [contrat commun](../docs/agents/skill-contract.md). Le Builder sélectionne les procédures proportionnées ; ni toute la bibliothèque ni quatre processus parallèles ne sont requis pour une petite tâche. Les reviewers gardent leur périmètre lecture/test/rapport ; un fichier n’ajoute aucune permission.

« Initialise un nouveau projet [nom] » ouvre le [parcours de démarrage](../docs/product/project-start.md). [initialize-project](initialize-project/SKILL.md) est chargé seulement pour sa séquence technique ou sa reprise ; sa référence d’environnement reste conditionnelle et les scripts existants restent les autorités d’exécution. Le Builder transmet ensuite le cadrage à analyze-brief/brief-to-specs et les tranches à [plan-feature](plan-feature/SKILL.md), puis aux procédures de réalisation/vérification, dans le mandat convenu. Aucun nouveau skill ni cycle systématique pour une correction. La [décision 002](../docs/decisions/002-dedicated-project-initialization.md) conserve cette séparation et la [décision 004](../docs/decisions/004-guided-project-start.md) définit le parcours.

Depuis la racine, après npm ci : `npm run validate:agent-kit`. Les [adaptations](../docs/agents/adapters.md), la [matrice](../docs/compatibility.md) et l’[historique de pratique sélectionné](../docs/agents/practice-history.md) distinguent structure, découverte et comportement effectivement éprouvés. Aucun retour au projet de fabrication nécessaire.
